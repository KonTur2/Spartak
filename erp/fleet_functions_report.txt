Отчёт о реализованных функциях в подпроекте Fleet (Управление флотом)
=====================================================================
Дата: 2026-03-19
Версия: 1.0

1. ОБЩЕЕ ОПИСАНИЕ ПРОЕКТА
-------------------------
Проект ERP Спартак — веб-приложение на Django для управления рыболовной компанией.
Подпроект Fleet отвечает за управление флотом: суда, экипаж, рейсы, техническое обслуживание.

2. РЕАЛИЗОВАННЫЕ МОДЕЛИ (БАЗА ДАННЫХ)
--------------------------------------
- Ship (Судно)
  * Поля: name, type, status, capacity, year_built, home_port, notes
  * Статусы: 'in_port' (в порту), 'at_sea' (в море), 'under_repair' (на ремонте)
- CrewMember (Член экипажа)
  * Поля: user (OneToOne), first_name, last_name, position, ship (ForeignKey), notes
  * При создании автоматически создаётся пользователь (User) и роль (UserRole) с ролью 'crew'
- Voyage (Рейс)
  * Поля: ship (ForeignKey), start_date, end_date, fishing_area, catch_plan, status, is_completed, crew (ManyToMany)
  * Статусы: 'planned' (запланирован), 'active' (активен), 'completed' (завершён)
- Maintenance (Техническое обслуживание/ремонт)
  * Поля: ship, type, start_date, end_date, cost, description, status

3. РЕАЛИЗОВАННЫЕ VIEW (КОНТРОЛЛЕРЫ)
-----------------------------------
Все view защищены декоратором @role_required, требующим роли 'director' или 'fleet_manager'.

3.1. Дашборд флота (fleet_dashboard)
  - Отображает список судов с текущим статусом.
  - Виджеты статистики: количество судов в море, в порту, на ремонте.
  - Таблицы текущих рейсов и последних ТО.
  - Кнопки быстрых действий: "Новый рейс", "Добавить судно", "Добавить сотрудника".

3.2. Детали судна (ship_detail)
  - Полная информация о судне.
  - Список закреплённого экипажа.
  - Таблица рейсов судна с колонками: дата начала, дата окончания, район промысла, план улова, статус, действия.
  - Кнопки действий для каждого рейса: "Редактировать", "Просмотр" (страница завершения рейса).
  - Таблица истории ТО.

3.3. Создание и редактирование судна (ship_create, ship_edit)
  - Полнофункциональные формы с валидацией.
  - Сохранение данных, редирект на детали судна.

3.4. Создание рейса (voyage_create)
  - Форма с выпадающим списком судов (все 10 тестовых судов).
  - Поля выбора даты убытия и прибытия (datetime-local).
  - Множественный выбор экипажа с улучшенным интерфейсом:
      * Поиск по ФИО в реальном времени.
      * Визуальное отображение выбранных членов экипажа в виде бейджей с возможностью удаления.
      * Синхронизация с hidden select.
  - Валидация пересечения рейсов: проверка, что судно не занято в указанный период.
  - Автоматическое изменение статуса судна на "в море" при создании рейса (если start_date <= now).
  - Привязка выбранного экипажа к рейсу (ManyToMany).

3.5. Редактирование рейса (voyage_edit)
  - Аналогична созданию, но предзаполняет данные существующего рейса.
  - Валидация пересечения рейсов с исключением текущего рейса.
  - Обновление статуса судна при изменении дат.

3.6. Завершение рейса (voyage_complete)
  - Отдельная страница для отметки рейса как завершённого.
  - Установка is_completed = True, статус рейса меняется на 'completed'.
  - Статус судна автоматически меняется на "в порту".

3.7. Создание члена экипажа (crew_create)
  - Форма ввода ФИО, должности, выбора судна, примечаний.
  - При сохранении создаётся пользователь (User) с логином на основе email (генерируется) и паролем.
  - Создаётся профиль UserRole с ролью 'crew'.
  - Редирект на список экипажа.

3.8. Список экипажа (crew_list)
  - Таблица всех членов экипажа с информацией.

3.9. Формы технического обслуживания (maintenance_create, maintenance_edit)
  - Создание и редактирование записей ТО.

4. РЕАЛИЗОВАННЫЕ ШАБЛОНЫ (HTML)
--------------------------------
- fleet/dashboard.html — дашборд флота.
- fleet/ship_detail.html — детали судна.
- fleet/ship_form.html — форма судна.
- fleet/voyage_form.html — форма рейса (с улучшенным выбором экипажа).
- fleet/voyage_complete.html — завершение рейса.
- fleet/crew_form.html — форма создания сотрудника.
- fleet/crew_list.html — список экипажа.
- fleet/maintenance_form.html — форма ТО.

5. ИНТЕГРАЦИЯ С ОСНОВНЫМ ПРОЕКТОМ
----------------------------------
- На главном дашборде (erp_app/dashboard.html) добавлена кнопка "Добавить сотрудника" в разделе быстрых действий.
- Навигационная панель (base.html) содержит пункт "Управление флотом" для директора и управляющего флотом.
- Используется система ролей из приложения accounts (декоратор role_required).

6. ТЕСТОВЫЕ ДАННЫЕ
------------------
Создано 10 судов с различными типами и статусами.
Создано 10 членов экипажа с ФИО (включая отчества в поле notes) и должностями.
Созданы тестовые рейсы и записи ТО (скрипт create_fleet_data.py).

7. ОСОБЕННОСТИ РЕАЛИЗАЦИИ
-------------------------
7.1. Автоматическое изменение статуса судна
  - В методе save модели Voyage реализована логика:
      * Если рейс активен (start_date <= now < end_date) и не завершён, статус судна меняется на "в море".
      * Если рейс завершён (is_completed=True), статус судна меняется на "в порту".
  - ПРОБЛЕМА: при создании запланированного рейса (start_date в будущем) статус судна всё равно меняется на "в море", что некорректно.
  - НЕОБХОДИМО ДОРАБОТАТЬ: статус должен зависеть от текущего времени относительно дат рейса.

7.2. Валидация пересечения рейсов
  - При создании/редактировании рейса проверяется, нет ли у выбранного судна других рейсов, пересекающихся по датам.
  - Если пересечение обнаружено, выводится сообщение об ошибке.

7.3. Улучшенный интерфейс выбора экипажа
  - Использован JavaScript для динамической фильтрации списка по введённому тексту.
  - Выбранные отображаются в виде цветных бейджей с крестиком для удаления.
  - Удобство для пользователя при работе с большим списком.

8. ТЕКУЩИЕ ПРОБЛЕМЫ И ЗАДАЧИ
-----------------------------
8.1. Статусы судов при планировании рейсов
  - Сейчас статус судна меняется на "в море" сразу после создания рейса, даже если рейс запланирован на будущее.
  - Требуется доработать логику, чтобы статус оставался "в порту" до начала рейса, а при наступлении start_date автоматически менялся на "в море".
  - Возможные решения:
      * Использовать фоновую задачу (celery/cron) для периодической проверки и обновления статусов.
      * Вычислять статус на лету при отображении (по наличию активного рейса в текущий момент) без изменения поля status.
      * Добавить поле "фактический статус", вычисляемое на основе рейсов.

8.2. Отсутствие автоматического перехода статуса при завершении рейса по дате
  - Сейчас рейс завершается только при ручном нажатии "Завершить рейс".
  - Нужно автоматически менять статус рейса на 'completed' при end_date <= now.

8.3. Оптимизация производительности
  - Некоторые запросы могут быть неэффективны (например, подсчёт статистики).
  - Рекомендуется добавить кэширование и индексы.

9. ИНСТРУКЦИЯ ПО ИСПОЛЬЗОВАНИЮ
-------------------------------
1. Войдите под учётной записью директора (логин: director, пароль: 123).
2. Перейдите в раздел "Управление флотом".
3. На дашборде вы увидите список судов и кнопки действий.
4. Чтобы создать рейс:
   - Нажмите "Новый рейс".
   - Выберите судно из выпадающего списка (10 судов).
   - Укажите даты убытия и прибытия.
   - В поле "Экипаж" начните вводить фамилию для фильтрации, выберите нужных членов экипажа.
   - Нажмите "Создать рейс".
5. Чтобы отредактировать рейс:
   - Перейдите на детали судна.
   - В таблице рейсов нажмите кнопку "Редактировать" у нужного рейса.
6. Чтобы добавить сотрудника:
   - На главном дашборде или в разделе флота нажмите "Добавить сотрудника".
   - Заполните форму и сохраните.

10. ЗАКЛЮЧЕНИЕ
--------------
Подпроект Fleet полностью функционален и готов к использованию.
Реализованы все основные CRUD-операции для судов, экипажа, рейсов и ТО.
Интерфейс удобен, есть валидации и улучшения UX.
Требуется доработка логики статусов судов для корректного отображения планируемых рейсов.
